# Блэкджек

Учебный проект для второй аттестации по объектно-ориентированному
программированию.

Реализованы модель блэкджека, консольное приложение и оконный интерфейс
на Swing. Механика отделена от ввода и вывода.

## Требования

- Java 21.
- Maven.
- Графическая среда для запуска Swing-интерфейса.

Из сторонних библиотек используется JUnit 5 для тестирования.

## Сборка и тестирование

Выполните команду из каталога с `pom.xml`:

```bash
mvn clean verify
```

Собранное приложение:

```text
target/Task2-1.0-SNAPSHOT.jar
```

## Запуск консольного приложения

```bash
java -cp target/Task2-1.0-SNAPSHOT.jar org.example.blackjack.console.BlackjackApplication
```

Запуск с заданным зерном:

```bash
java -cp target/Task2-1.0-SNAPSHOT.jar org.example.blackjack.console.BlackjackApplication 42
```

## Запуск оконного интерфейса

```bash
java -cp target/Task2-1.0-SNAPSHOT.jar org.example.blackjack.ui.BlackjackUiApplication
```

Запуск с заданным зерном:

```bash
java -cp target/Task2-1.0-SNAPSHOT.jar org.example.blackjack.ui.BlackjackUiApplication 42
```

В IntelliJ IDEA можно запустить метод `main()` соответствующего класса.
Зерно указывается в поле `Program arguments` конфигурации запуска.

## Воспроизводимость

Первый аргумент командной строки — необязательное зерно генератора
случайных чисел типа `long`.

Если аргумент отсутствует, зерно выбирается по текущему времени.
Использованное значение выводится в консоли или в окне приложения.

Все игровые случайные величины получаются из одного генератора.
При замене башмака используется тот же генератор без повторной
инициализации.

Для повторения партии должны совпадать:

- Зерно.
- Начальный состав игроков, их балансы и ставки.
- Правила стола.
- Последовательность действий, включая изменения состава участников.

Изменение размера окна или масштаба интерфейса не меняет состояние игры.

## Управление в консоли

В начале игры создаются два игрока с балансом 100.
Основная ставка каждого игрока — 10.

Действия выбираются числом:

| Команда | Действие |
|---------|----------|
| 1 | Взять карту |
| 2 | Остановиться |
| 3 | Удвоить ставку |
| 4 | Разделить пару |
| 5 | Сдаться |

При предложении страховки вводится ее сумма.
Ноль означает отказ от страховки.

После завершения раздачи:

- `1` — начать следующую раздачу.
- Другое значение — завершить игру.

Балансы сохраняются между раздачами. Игроки, которым не хватает денег
на основную ставку, пропускают раздачу.

После завершения игры выводится рейтинг по убыванию баланса.
При равных балансах используется порядок по возрастанию идентификатора.

## Управление в оконном интерфейсе

Слева расположена таблица участников с именами, идентификаторами,
балансами и ставками.

Между раздачами доступны операции:

- `+` — добавить игрока, указав имя, начальный баланс и ставку.
- `−` — удалить выбранного игрока.
- `Ставка` — изменить ставку выбранного игрока.
- `Баланс` — пополнить баланс выбранного игрока.

Во время раздачи изменение состава, ставок и пополнение заблокированы.

Для начала используется кнопка `Начать раздачу`.
После завершения становится доступна кнопка `Следующая раздача`.

Игровые действия выполняются кнопками внизу окна.
Доступность действий запрашивается у модели; недоступные кнопки
блокируются.

При предложении страховки игрок вводит сумму и выбирает покупку
или отказ. Решение принимается отдельно каждым участником.

Ход дилера и расчет выплат выполняются автоматически после завершения
действий игроков.

В журнале отображаются ставки, действия, переходы фаз, решения
о страховке и результаты расчетов.

### Масштабирование

В правом верхнем углу находится выбор масштаба:

- `Авто` — размер элементов зависит от размера окна.
- `100–200%` — ручной масштаб.

Масштабируются шрифты, карты, строки таблицы и отступы.
Карты и длинные подписи переносятся по ширине.
При необходимости доступна прокрутка игрового стола и журнала.

## Правила стола

### Карты и очки

- Числовые карты дают указанное на них количество очков.
- Валет, дама и король дают по 10 очков.
- Туз считается за 11 или за 1, чтобы получить наибольшую сумму
  без перебора.
- При превышении 21 фиксируется перебор.
- При достижении 21 действия рукой автоматически завершаются.

### Ставки и выплаты

Основная ставка списывается при ее принятии.

| Результат | Полный возврат при ставке 10 |
|-----------|-----------------------------|
| Проигрыш | 0 |
| Ничья | 10 |
| Обычный выигрыш | 20 |
| Начальный блэкджек | 25 |
| Сдача | 5 |

Полный возврат включает возвращаемую собственную ставку.

Начальный блэкджек — 21 очко из двух исходных карт.
Он оплачивается с прибылью 3:2.

Если начальный блэкджек есть одновременно у игрока и дилера,
фиксируется ничья.

### Дилер

- Дилер получает две начальные карты.
- До раскрытия показывается только первая карта.
- Блэкджек дилера проверяется до действий игроков.
- При открытом тузе сначала завершается выбор страховки.
- Дилер добирает карты при сумме меньше 17.
- На мягких 17, например туз и шестерка, дилер останавливается.
- Если сравнивать руки не требуется, дилер пропускает добор.

### Удвоение

- Разрешено для активной руки из двух карт.
- Списывается еще одна сумма, равная текущей ставке.
- Ставка руки удваивается.
- Выдается ровно одна дополнительная карта.
- После этого действия рукой завершаются.
- После разделения удвоение разрешено, если рука остается активной.

### Разделение

- Разделяются две карты одинакового достоинства.
- Одинаковая стоимость разных достоинств недостаточна:
  например, десятка и валет не образуют разделяемую пару.
- Создаются две руки с одинаковыми ставками.
- Списывается одна дополнительная ставка.
- Каждая новая рука получает дополнительную карту.
- Максимум четыре руки у одного игрока.
- Повторное разделение разрешено в пределах этого ограничения.
- После разделения тузов каждая рука получает только одну карту
  и останавливается.
- Две карты с суммой 21 после разделения считаются обычными 21,
  а не начальным блэкджеком.

### Сдача

- Разрешена только для активной исходной руки из двух карт.
- После разделения сдача запрещена.
- При расчете возвращается половина ставки.

### Страховка

- Предлагается при открытом тузе дилера.
- Хранится отдельно от основной ставки.
- Максимальная сумма — половина основной ставки.
- Для продолжения нужны решения всех участников.
- При блэкджеке дилера страховка выигрывает с прибылью 2:1.
- Полный возврат равен трем страховым ставкам.
- При отсутствии блэкджека дилера страховая ставка проигрывает.

### Башмак

Новый башмак содержит минимум шесть колод.
Для большого числа участников количество колод увеличивается.

Используется консервативный запас карт на полную раздачу:

```text
запас = количество участников × 4 × 21 + 17
```

Учитываются до четырех рук на игрока, до 21 карты в каждой руке
и до 17 карт у дилера.

Если в текущем башмаке достаточно карт, он используется дальше.
В противном случае до приема ставок создается новый башмак.

Количество колод в новом башмаке выбирается так, чтобы покрыть
требуемый запас. Например, для восьми участников запас составляет
689 карт, поэтому подготавливается 14 колод — 728 карт.

### Основные классы модели

| Класс | Назначение |
|-------|------------|
| `Card` | Неизменяемая карта |
| `Rank`, `Suit` | Достоинство и масть |
| `Hand` | Упорядоченный набор карт |
| `HandEvaluator` | Подсчет очков с учетом тузов |
| `Money` | Неизменяемая денежная сумма |
| `PlayerId` | Идентификатор игрока |
| `Player` | Игрок и его баланс |
| `Shoe` | Создание, перемешивание, подготовка башмака и выдача карт |
| `RoundHand` | Рука со ставкой, состоянием и признаком разделения |
| `BlackjackRound` | Фазы, очередность действий и расчет результатов |
| `InsuranceDecision` | Решение о страховке и ее сумма |
| `HandView` | Неизменяемый снимок руки |
| `GameEvent` | Общий тип событий раздачи |

Модель не выполняет консольный или графический вывод.
Интерфейсы получают снимки состояния и журнал событий.

### Фазы раздачи

- `BETTING` — прием ставок.
- `INITIAL_DEAL` — начальная раздача.
- `INSURANCE` — решения о страховке.
- `PLAYER_TURNS` — действия игроков.
- `DEALER_TURN` — ход дилера.
- `SETTLEMENT` — расчет результатов.
- `FINISHED` — завершенная раздача.

Некоторые фазы пропускаются в зависимости от ситуации,
например при начальном блэкджеке дилера.

### События

- `BetPlacedEvent` — принята основная ставка.
- `PhaseChangedEvent` — изменилась фаза.
- `PlayerActionEvent` — выполнено действие игрока.
- `HandSettledEvent` — рассчитан результат руки.
- `InsuranceDecisionEvent` — принято решение о страховке.
- `InsuranceSettledEvent` — рассчитана страховая ставка.

## Примененные решения

### Инкапсуляция

Поля модели закрыты. Списки карт, событий и снимков возвращаются
неизменяемыми копиями.

Снимок `HandView` не меняется после последующего изменения руки.

### Неизменяемые значения

`Card`, `Money`, `PlayerId` и другие значения представлены через `record`.

Для денег используется `BigDecimal`.
Денежные операции возвращают новый объект `Money`.

### Наследование и полиморфизм

Абстрактный класс `GameAction` задает общий метод `execute()`.

Конкретные действия реализованы наследниками:

- `HitAction`.
- `StandAction`.
- `DoubleAction`.
- `SplitAction`.
- `SurrenderAction`.

Приложение работает с общим типом `GameAction`.

### Паттерн «Команда»

Объект действия хранит идентификатор игрока и индекс руки.
Вызов `execute(round)` передает выполнение механике раздачи.

Один и тот же набор команд используется консольным и оконным
интерфейсами.

### Перечисления с поведением

`HandOutcome.payout()` рассчитывает полный возврат по ставке.

`HandStatus.isFinished()` определяет завершенность действий рукой.

`InsuranceStatus.isDecided()` определяет принятие решения о страховке.

### Коллекции и обобщенные типы

Применяются типизированные коллекции, например:

- `List<Card>`.
- `List<Player>`.
- `Map<PlayerId, List<RoundHand>>`.
- `Map<PlayerId, InsuranceDecision>`.
- `Set<ActionType>`.

`LinkedHashMap` сохраняет порядок участников.
`EnumSet` используется для формирования доступных действий.

### Компараторы и лямбды

Итоговый консольный рейтинг сортируется через `Comparator`:

1. По убыванию баланса.
2. При равенстве — по возрастанию идентификатора.

Лямбды извлекают значения для сравнения.
Сортируется копия списка, поэтому очередность ходов сохраняется.

В Swing лямбды также используются для обработчиков кнопок.

## Тесты

Тестирование выполняется через JUnit 5.

Проверяются:

- Подсчет очков и изменение стоимости тузов.
- Равенство и `hashCode` объектов-значений.
- Денежные операции и недостаток средств.
- Состав и воспроизводимость башмака.
- Недопустимые действия и переходы фаз.
- Полные раздачи с фиксированным зерном.
- Выплаты за выигрыш, проигрыш, блэкджек и сдачу.
- Удвоение и разделение.
- Особенности разделения тузов.
- Страховка и ожидание решений всех участников.
- Сокрытие карты дилера.
- Неизменяемость снимков и журнала.
- Подготовка башмака для большого числа участников.
- Доступность действий с учетом состояния руки и баланса.
